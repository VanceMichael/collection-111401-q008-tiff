# 航测影像目录的窗口资料领取

按地块取得影像目录、窗口和分辨率约束后，只领取窗口覆盖的瓦片字节，并把质检交接写入收件库；原始收件端也能人工保存整个影像文件。

## 窗口领取与质检交接

`receivePlotWindow(base, directory, options)` 是窗口领取业务入口：

- 先取目录并收存，按 `maxPixelSize` 选层：只接受像素尺度不超过上限的层并取其中最细的，被跳过的层及原因记入交接；没有满足的层时明确失败，绝不为节省流量悄悄换层。
- 对所选层只发 Range 请求：影像头、目录、所需标签值和与窗口相交的瓦片，跨瓦片窗口按行列位置拼接，不错位；Deflate 瓦片解压后校验尺寸。
- 一次尝试内所有请求绑定同一 ETag（If-Match），遇到 412、ETag 漂移或长度变化即整次重来（默认最多 3 次），并在结束前复核目录未变；重试耗尽则明确失败，不留下完成的交接。
- 完成后交接清单（`window-qc-handoff`）最后落库，内含：实际取得的像素范围、无效值游程、所用影像版本（ETag 与目录版次）、所选层与被拒层、逐瓦片字节范围与摘要、窗口定位坐标、领取字节数（可与来源 state.transferred 核对）。没有清单即没有完成。
- `options.window` 可覆盖目录默认窗口；窗口越出影像时按实际交集交付，影像外区域以目录无效值填充并计入无效区域。元数据不完整或编码不受支持时明确报错，不静默误读。

## 运行

使用 Node.js 22。依赖版本已锁定，运行、测试和演示不下载任何数据或软件。运行时只使用 Node.js 内置模块。

- `npm test`：执行本地来源交互及收件存储测试。
- `npm run build`：逐个检查模块语法。
- `npm run demo`：启动本地来源，运行当前领取流程，打印真实收件结果后退出。
- `npm start`：在 127.0.0.1:8080 启动本地来源，PORT 可调整。`GET /health` 返回服务与当前来源版本；原有 `/_health` 仍可使用。

容器方式：`docker build -t collection-tiff .`，然后 `docker run --rm --network none collection-tiff`。镜像构建属于环境准备，运行时不访问公网。

## 项目结构

`src/domain.mjs` 提供窗口领取业务入口 `receivePlotWindow` 与原有人工读取入口；`src/window.mjs` 负责带版本绑定的 Range 窗口领取，`src/tiff.mjs` 严格解析小端瓦片 TIFF 子集，`src/raster.mjs` 负责窗口与瓦片网格的换算、拼接和无效值扫描；`src/client.mjs` 负责人工指定地址的有限大小原始领取；`src/archive.mjs` 保存内容及来源凭据。`provider/` 是独立的本地来源服务，`docs/source-contract.md` 说明它的资料和状态约定。演示使用临时目录，正式接入可向业务入口传入持久目录。

本地服务中的机构、记录和文件都是合成业务资料，不使用真实账号、个人信息或第三方站点数据。当前演示通常十秒内结束，全部本地测试应在六十秒内结束。
